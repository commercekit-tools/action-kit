# Extraction audit

Read-only local inspection was compared with GitHub main and open PRs on 2026-11-08. Exact SHAs and schema provenance are in `compatibility/baselines.json`. Notify and Build had no open PRs. Deploy main contains only its starter; open implementation PR #1 at `85baaaa01d114473cb662e2394e752e87a8f123d` is the intended implementation baseline. No consumer files were changed.

Files inspected: Notify `schema/notification-event-v1.schema.json`, `src/event/{types,validate,parse,enrich-context,sanitize}.ts`, `src/presentation/create-presentation.ts`, provider renderers and `src/delivery/{webhook,retry-after,url-validation}.ts`; Build and Deploy `src/{auth,http,api,notification,security,inputs,errors,result,action}.ts` and vendored contracts.

The v1 schema was not redesigned. Timeout is not a new v1 status: synthetic timeout fixtures use `internal-error` with `error.code=TIMEOUT`. Prepare-canary handoff uses deployment `action-required` and `decisionType=PREPARE_CANARY`. No CLI diagnostics, polling, cancellation, traffic-split, lifecycle logic, Slack or Teams rendering was extracted.

RECONCILE means an explicit public primitive that can express both consumer requirements, not a consumer migration. Runtime integration against published packages and real Sandbox scenarios remains a later coordinated gate.
