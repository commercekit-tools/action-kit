# Architecture

Two focused ESM libraries form independent boundaries. `notification-contract` owns NotificationEvent v1, not notification delivery. `ccv2-client` owns authentication and HTTP mechanics, not CCv2 business operations. The root workspace is private. Only `packages/*` are workspace members; compatibility adapters are private test source, not packages.

Notify → notification-contract. Build and Deploy → notification-contract + ccv2-client. Future Check and reusable workflows → notification-contract. Neither library imports the other or `@actions/core` / `@actions/github`.

The contract schema is copied from Notify main at the exact SHA in `compatibility/baselines.json`. `src/schema.ts` embeds the identical JSON for a filesystem-free runtime; a parity test compares it with the canonical schema file. JSON Schema handles version, event/status compatibility, counts and bounds. Additional semantic HTTPS checks apply to links and run URLs. Additive v1 fields remain accepted by validation; factories select supported data, source, link and safe error fields. Factories accept normalized producer data rather than raw API responses. They validate the result; callers sanitize any untrusted human-readable text first.

`extractSafeGitHubContext` reads only the approved runner fields. It rejects malformed repositories, run IDs, attempts and unsafe server origins. It never reads an event payload. Producer merge applies explicit producer values before filling gaps; factories can generate a run URL from extracted runner identity. Notifier merge preserves additive producer context and fills only missing/empty values; it never overwrites valid producer identity. The functions are separate public operations even where their current fill-only behavior overlaps. Callers must avoid mixing unrelated producer and notifier runs when providing enrichment; explicit producer run URLs always win.

The transport requires a policy for every request. `token` and `safe-read` allow bounded transient retries; `unsafe-mutation` permits one attempt for network, timeout, 429 and selected 5xx outcomes. A caller can explicitly opt into one 401 invalidation/replay for any policy. There is no method-based inference. Bodies must be replayable strings or bytes, not streams. Consumers own mutation ambiguity classification and endpoint-specific status/shape validation.

All bodies are streamed with a byte bound and request abort signal. JSON content types support objects, arrays and primitives; zero-byte bodies are empty; other content types remain binary. Error response bodies are discarded except bounded, redacted problem facts. Consumers decide whether to show those facts. No logging, telemetry, persistence, build/deployment operations or step summaries exist in either library.
